## High-level view

Finder 菜单把每条命令绑定到一次菜单构建得到的 `selectedURLs` 与目标目录，点击后不再查询 Finder；永久删除从这份快照生成 path、resolved path、device/inode 快照，由扩展在主 App 批准后执行。主 App 只解析受控请求、展示确认并带回请求摘要，没有取得删除执行权。

安全偏好使用唯一的 `SafetyPreferencesStore.save` 写入口，读取、schema、文件类型、所有者、权限或一致性校验失败时都退回 `confirmBeforePermanentDelete = true`。免确认分支会读取两次，只有两次都是 `false` 且 revision 相同才跳过主 App；这部分要求仍完整。

确认请求把 ID、绝对 `createdAt`、动作、路径、确认模式和回复 socket 编入 SHA-256 摘要；扩展侧还校验回复进程 PID 对应的 host CDHash。socket 使用非阻塞 connect/read/write 和有界 poll，外层任务以 `createdAt + 120s` 的剩余寿命终止；分布式通知只承担不可信唤醒。

本地化通过配置内语言即时重建 Finder 菜单和状态栏菜单，只翻译仍保持历史默认名称的内置目录/Terminal，旧配置缺少 language、bundleIdentifier 等字段时继续回填。资源在当前工作树构建产物中存在，但 **confirmed** 它们尚未进入版本控制，干净检出无法重现本次成功构建。

## 最终路径身份没有绑定到删除提交

**High — confirmed.** `revalidateDeletionTargets` 会比较原始 path、resolved path、受保护路径状态以及 device/inode，但返回后 `executePermanentDeletion` 再次按字符串 URL 调用 `FileManager.removeItem`（`FinderExtension/FeatureServices.swift:1203-1233`）。另一个进程可以在最后一次 `lstat` 之后、`removeItem` 解析路径之前 rename/swap 同名入口，扩展随后删除替换项。免确认分支还把目标复核放在第二次安全偏好文件读取之前（`FinderExtension/FeatureServices.swift:1162-1168`），进一步扩大窗口。

应把最终提交改成身份绑定的流程，例如在同一父目录中以不可覆盖的原子 rename 将入口移入随机隔离名，复核隔离项的 device/inode、resolved path 与保护规则后再删除；不匹配时恢复且拒绝。至少应把最后一次逐项复核移到所有偏好读取之后并紧邻提交，同时增加可控 rename/swap 测试；单纯再加一次 path-based `lstat` 仍不能完全消除 check/use 竞态。

## 菜单快照与确认进程边界

`FinderSync` 在构建菜单时只读取一次 selection/target，并把同一 `MenuInvocationContext` 绑定到所有 tag；点击永久删除时复制该快照并异步交给扩展内的 `FeatureCoordinator`（`FinderExtension/FinderSync.swift:74-122, 206-211`）。主 App 只展示项目数量，响应包含 request ID、原请求的 `authenticationDigest` 和批准位（`App/SuperRightClickApp.swift:68-181`），实际 `removeItem` 仅存在于扩展。

请求文件要求私有目录、当前 UID、普通单硬链接文件、窄权限，并在读取前后比较 fd 和路径的 device/inode。回复 socket 在扩展侧读取 `LOCAL_PEERPID`，验证运行进程的签名 CDHash 与宿主 bundle 静态 CDHash 一致，再校验 request ID 和 digest；120 秒绝对期限同时约束请求读取、App modal、扩展等待和最终接受结果。分布式通知不参与授权判断。

## SafetyPreferencesStore 的 fail-closed 与稳定双读

`SafetyPreferencesStore.load` 对目录、文件、schema 或 JSON 的任一异常返回启用确认的安全默认值；生产代码只有设置模型调用 `save`，Finder 扩展每次删除即时读取。确认关闭路径先读取 `false/revision A`，复核目标后再读取一次，第二次变为 true 或 revision 改变时都会回到主 App 确认；设置保存失败则 UI 恢复先前值。

## 本地化、格式串与兼容行为

自定义 action 名称直接返回而不作为 format string；模板、App 和目录名称只作为 `%@` 参数插入，因此用户名称中的 `%` 不会被二次解释。默认目录和 Terminal 只有在名称、路径或 bundle identity 仍匹配历史默认值时才翻译，编辑后的名称原样显示；`MenuConfiguration` 对旧 language/openWithApps/bundleIdentifier 字段继续提供默认值。配置保存新增进程内通知，`AppLifecycleModel` 收到语言变化后会重建现有状态栏菜单。
